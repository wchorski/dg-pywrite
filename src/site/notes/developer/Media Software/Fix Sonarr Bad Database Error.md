### What’s wrong

In that thread, the `Languages` column (column 11) was corrupt. In your log it’s the **`MediaInfo` column (column 8)**, in one specific file: _Pokémon S01E14 – Electric Shock Showdown_.

The stored `rawStreamData` JSON for that file has corrupted bytes. In the first audio stream’s tags, `\u0022DURATION-eng\u0022:` has become `\u0022DURATION-eng\u002::`, which is invalid JSON. Further down there’s also a mangled `\u0822` and some stray `(` characters. This looks like a bad write to the database, not a problem with the video file.

Sonarr loads all episode files for a series in one query, so one bad row breaks the whole Pokémon series page (“Unable to load episode files”). Don’t run the forum’s `UPDATE EpisodeFiles SET Languages...` command. It would overwrite the language on every file in your library and wouldn’t fix this.

## **throwaway container (works anywhere)**

Stop Sonarr first, then replace the path with wherever your Sonarr config folder is (the one containing `sonarr.db`):

bash

```bash
docker stop sonarr
cp ./sonarr/sonarr.db ./sonarr/sonarr.db.BAK

docker run --rm -it -v ./sonarr:/config alpine \
  sh -c "apk add --no-cache sqlite && sqlite3 /config/sonarr.db"
```

That drops you at a `sqlite>` prompt. Then run:

sql

```sql
SELECT Id, RelativePath FROM EpisodeFiles WHERE RelativePath LIKE '%Electric Shock Showdown%';
╭─────┬───────────────────────────────────────────────────────────────────────╮
│ Id  │                             RelativePath                              │
╞═════╪═══════════════════════════════════════════════════════════════════════╡
│ 319 │ Season 1/Pokémon () - S01E14 - Electric Shock Showdown HDTV-1080p.mkv │
╰─────┴───────────────────────────────────────────────────────────────────────╯
```

```sql
UPDATE EpisodeFiles SET MediaInfo = NULL WHERE Id = 319;
SELECT Id, RelativePath FROM EpisodeFiles WHERE MediaInfo LIKE '%\u002::%';
.quit
```

Then `docker start sonarr`, open the series, and run **Refresh & Scan**.
